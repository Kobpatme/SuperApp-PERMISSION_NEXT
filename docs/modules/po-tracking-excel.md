# นำเข้า PO จาก Excel

หน้า `/po-tracking/new` เลือกกรอกเองหรือนำเข้า Excel ได้ การนำเข้าใช้สิทธิ์ `po_tracking.import.manage`, `po_tracking.po.manage` และ `po_tracking.price.read` ร่วมกัน และตรวจ session/สิทธิ์ซ้ำทุก server action

## ไฟล์ที่รองรับ

- `.xlsx` ไม่เกิน 512 KB, ข้อมูล 1–1,000 แถว ใช้ชีตแรก
- ค้นหาหัวตารางใน 20 แถวแรก ตัดช่องว่างนำหน้า/ท้ายและยุบช่องว่างซ้ำ จับคู่ชื่อโดยไม่แยกตัวพิมพ์ใหญ่เล็ก สลับตำแหน่งคอลัมน์ได้
- หัวตารางอ้างอิง: Material, Description, BUn, PO No., PO Rel.Date, LastGRdate, Stock, Order QTY, Actual GR, Outstanding, ETA, Unit Price, PO Amount, Project code, Vendor, Name (รองรับชื่อเดิม Order ในไฟล์เก่าด้วย)
- เพิ่ม `Note` หรือ `หมายเหตุ` ได้ หากไม่มีค่าหมายเหตุ จะรักษาหมายเหตุเดิมไว้
- วันที่รองรับ `dd.mm.yyyy`, `dd/mm/yyyy`, `yyyy-mm-dd` และ Excel serial แบบ 1900 ไม่รองรับ workbook ที่ใช้ระบบวันที่ 1904
- รหัสเป็นข้อความและรักษาศูนย์นำหน้า เลขที่ Excel บันทึกเป็นตัวเลขจนศูนย์หายแล้วไม่สามารถกู้คืนอัตโนมัติได้
- ใช้ decimal.js และความละเอียดเดียวกับ schema/ตัวนำเข้าเดิม: จำนวน/ราคาสี่ตำแหน่ง มูลค่าสองตำแหน่ง ช่องว่างไม่แปลงเป็นศูนย์
- ราคาต่อหน่วยเว้นว่างได้ ทั้งกรอกเองและ Excel เก็บเป็น NULL แยกจากราคา 0; รายการกรอกเองที่ยังไม่ทราบราคาจะยังไม่คำนวณมูลค่า และรายงานแสดงจำนวนรายการที่มูลค่ายังไม่ทราบ

## ตรวจซ้ำและอัปเดต

จับคู่ระดับรายการด้วยเลข PO + รหัสวัสดุ ไม่ใช้เลขแถวหรือเลข PO อย่างเดียว หากคู่นี้ซ้ำในไฟล์หรือฐานข้อมูลหลายแถว จะไม่เลือกจับคู่แทนผู้ใช้และไม่อนุญาตบันทึกแถวนั้น ผู้ใช้ต้องแยก/แก้ข้อมูลหรือจัดการจากหน้ารายละเอียดก่อน

รายการใหม่ถูกเลือกไว้ใน preview รายการอัปเดตต้องเลือกเอง ดูค่าเดิมและค่าจากไฟล์ก่อนยืนยัน เมื่อข้อมูลหลักเหมือนเดิม อนุญาตอัปเดตเฉพาะ ETA และหมายเหตุ ตามนโยบายที่ผู้ใช้ยืนยัน 11/11/2569 จำนวน ราคา หน่วยนับ รหัสผู้ขาย และข้อมูลหลักอื่นที่ต่างกันเป็น conflict และไม่ถูกทับ

`Actual GR` เปรียบเทียบกับยอดรับตั้งต้น + ใบรับที่ยังไม่ยกเลิก ไม่เขียนทับยอดตั้งต้นหรือสร้างใบรับแทนประวัติเดิม แถวที่ผิดหรือขัดแย้งไม่ถูกบันทึก ส่วนแถวที่ผ่านสามารถเลือกบันทึกได้

## การบันทึก

Preview ไม่เขียนฐานข้อมูล ยืนยันแล้วจะอ่านไฟล์และตรวจข้อมูลซ้ำใหม่ภายใน transaction พร้อมตรวจ digest ของ preview/version ป้องกันข้อมูลเปลี่ยนกลางทาง ล็อกตาราง PO/receipts ระหว่างการยืนยันเพื่อป้องกันนำเข้าซ้ำพร้อมกันและอ่านยอดรับที่เปลี่ยนกลางทาง ต้องยืนยันใหม่หากข้อมูลเปลี่ยน

รายการใหม่มี source_import_runs/source_import_rows และ checksum แยกจากรายการนำเข้ารอบเดิม การเพิ่ม/อัปเดตเขียน audit พร้อมข้อมูลใน transaction เดียว หาก audit ล้มเหลว rollback ทั้งชุด การอัปโหลดไม่แก้ schema, grants หรือสิทธิ์ผู้ใช้ ฐานต้องมี migration 0066 เพื่อรองรับราคาที่ยังไม่ทราบ และใช้การเปรียบเทียบ NULL-safe เพื่อรักษาข้อมูลนำเข้าเดิม

## การทดสอบ

`npm test -- src/modules/po-tracking/excel-domain.test.ts` ตรวจ mapping, ไฟล์อ้างอิงจริง, validation, duplicate/ambiguity, การอัปเดตและ conflict

`node scripts/po-excel-test-db.mjs` สร้างฐาน clone ชั่วคราวจาก local staging ชื่อ `permission_superapp_staging_20261104_1157` ทดสอบสิทธิ์ การเพิ่ม/อัปเดต audit/lineage, replay, stale preview, concurrency และ rollback แล้วลบเฉพาะ clone ของการทดสอบ ไม่เขียน staging

หาก staging มี session ใช้งานอยู่ ชุดทดสอบใช้ pg_dump/pg_restore ทำ snapshot โดยไม่ปิด session ตั้ง PO_TEST_PG_BIN เมื่อเครื่องมือนี้ไม่อยู่ในตำแหน่ง portable/PATH

`node scripts/po-excel-browser-fixture.cjs` เปิดเว็บ production build บน 3106 พร้อม synthetic login และไฟล์ทดสอบใน .data ใช้ฐาน po_browser_test_* แยก ทดสอบจริง 11/11/2569 แล้ว: login → อัปโหลดคอลัมน์สลับและราคาว่าง → preview → เพิ่ม 1 รายการ → นำเข้าไฟล์อัปเดต → แสดง diff/เลือกเอง → อัปเดต 1 รายการโดยยอดรายการยังเท่าเดิม → สร้าง PO แบบกรอกเองโดยเว้นราคา ตรวจ persisted NULL และ audit บน clone แล้ว หยุด fixture เพื่อลบ clone เฉพาะของการทดสอบ
